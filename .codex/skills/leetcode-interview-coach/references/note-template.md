# 学习笔记内容与排版规范

收尾时必读。以 [E70 用户参考稿](https://www.yuque.com/dcczf/fbtgtc/mtunxpclg9lt77rt) 的「可回看学习过程，也可直接查答案」为原则，不复制其偶然的排版问题。参考稿只读，不作为发布目标。

## 一份素材、两种呈现

主代理从当前题真实对话提取有序 `teachingTranscript`、有效 `solutionVariants` 和简短 `conversationDigest`，字段见 `conversation-digest-schema.md`。脚本不读取聊天、不补造教学，也不把摘要扩写成对话。缺失历史要在相应位置明确标记；能从用户提供的参考稿恢复时注明来源。

`render_learning_note.py` 统一生成内容段落及仓库 Markdown，`render_yuque_lake.py` 将同一内容转换为语雀原生富文本。不要为仓库和语雀另写两套总结。旧 `noteContent` payload 仍可使用，不强制迁移历史笔记。

## 文档顺序

1. **题目入口与题干**：标题如 `E70-爬楼梯`（题号去前导零，保留 E/M/H 难度前缀），附原题链接。完整题干、示例和限制默认折叠；普通题干是正文，不伪装成 Java。语雀使用文档标题字段，正文不重复插入同名一级标题。
2. **GPT 教学流程**：默认折叠，按真实顺序保留「教学讲解／提问 → 我的回答／代码 → 反馈 → 后续优化」。GPT 讲解用引用，用户回答用标明身份的普通正文。代码使用正确语言的代码块，不把整个对话标成代码。
3. **答案版本**：教学过程外单列确实存在的有效解法，各附简短用途、时间与额外空间复杂度。最终版本展开，其余版本折叠。只有一个版本就只展示一个，不把数组版／滚动版机械套到其他题。
4. **本次训练记录**：展开。记录真实第一反应、突破、卡点、实现表现及掌握程度。无错误就写未观察到算法错误，不编造失败经历。
5. **复杂度与边界**：展开。区分各版本，并解释本题真实边界、类型范围及关键初始化。
6. **面试表达与复习**：展开。给出简洁可口述思路和有针对性的二刷动作，不把复习建议自动变成定时提醒。

构建、提交、推送、环境、接口限流和发布状态写在收尾报告／审计结果，不混进教学正文。摘要只用于简短训练记录及知识索引，不再在完整正文末尾重复追加整份摘要。

## 原代码与注释保真

- **保留用户自己写的注释、变量名和实现结构。** 默认仅规范缩进、空白、代码块语言。
- 教学记录保留历史尝试，不把错误版本悄悄替换成最终答案。对应位置加「勘误／更新说明」，区分用户误解与教练口误。
- 错误或过时注释原样保留，在代码块相邻位置解释其现状；不得擅自删除、改写。
- 单列有效答案必须可复制编译，必要算法／语法修正应明确说明差异。原本正确就不声称修复了算法。
- E70：`new int[n + 1]` 在 `n = 1` 时允许访问 `dp[1]`，教练先前否定这点的句子是口误。用户数组版 `dp[i] = f(i + 1)`，故 `f(n) = dp[n - 2] + dp[n - 3]`（`n >= 3`）；旧注释中的 `dp[n-2]+dp[n-1]` 混用了台阶编号和数组下标，应旁注勘误。滚动版沿用的「创建数组」注释已过时，但仍保留。

## 排版约束与验收

使用清楚的标题层级、行内代码、必要的加粗与链接。加粗聚焦核心结论、边界、更新顺序；避免整段加粗、复杂嵌套折叠或装饰符号。

仓库用 `<details><summary>…</summary>` 表示折叠；语雀必须使用已验证的 Lake 原生结构，不能假定普通 Markdown 的 `<details>` 自动转为原生折叠。发布前本地预览及只读 dry-run；发布后重新读取正文并在浏览器实际展开／收起核验。原生折叠无法可靠保存时保留本地产物，明确报告排版未完成，不用纯文本降级冒充成功。

检查完整问答顺序、代码与注释字符、中文编码、最终答案可直接阅读；正文不得出现 JSON／Python 字面量、英文内部字段名或 Codex 标记。仓库保留既有标记区时，只替换授权区域。
