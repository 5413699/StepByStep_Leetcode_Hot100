1.为什么二维数组外层遍历行，内层遍历列的效率远高于外层遍历列，内层遍历行？
这是数组的缓存与局部性原理导致的
（缓存）
cpu执行计算时，要先从内存中读取数据，才能进行计算
内存的读写速度是纳秒级别（10的-9次方）
cpu的运算速度是皮秒级别（10的-12次方）
内存读取数据的速度跟不上cpu的运算速度，会导致效率上的浪费
为了解决这个问题，在cpu和内存之间引入缓存
每次计算时，优先找缓存中的数据，再去内存中读取数据

一开始缓存是空的，需要将内存中的数据读入缓存中，
一次存多少？一次只读一个int不划算，
因此实践中一次向缓存中64字节，
将这64个字节成为一个缓存行cacheline，作为缓存读写的最小单位


在实际操作中，我们会将这个数据连同其临近的数据凑成一个缓存行读入内存中，
这就是数组的空间局部性原理

体现在在实际数组读取时，假如外层遍历行，内层遍历列
循环在读取[0,0]时，不只会读取该元素本身
还会读取其临近的数据 【0，false数组对象头假设8字节】，[0,0]、[0,1]、[0,2]...[0,13]
读取[0,1]、[0,2]...时，发现已经被读取在缓存中，无需重新读取，
因此外层遍历行，内层遍历列能够充分利用缓存，提高效率

（同理读取[1,0]时，缓存1，false，[1,0]、[1,1]、[1,2]...[1,13],这里的1，false指的是数组的对象头）


假如外层遍历行，内层遍历列
读取[0,0]时，缓存[0,0]、[0,1]、[0,2]...[0,13]
接下来读取[1,0]时，缓存中没有，又要从内存中读取，
缓存没有被有效利用，但缓存大小有限，因此会覆盖掉之前的数据
比如缓存只有八行，读取[8,0]时缓存中的[0,0]、[0,1]、[0,2]...[0,7]被覆盖了
此时读取[0,1]时，缓存没用上，又要重新调用内存读取，效率低


缓存行的大小为什么是64字节？
程序访问某个内存地址时，大概率会访问其附近的数据
64 字节足够容纳多个连续元素（如 16 个 int 或 8 个 long）
如果缓存行太小：无法充分利用局部性，且多个线程修改不同变量但位于同一缓存行时，会导致缓存失效
太大：会加载很多用不到的数据，浪费缓存空间，存储的缓存行数量就少
64 字节能在缓存命中率和空间利用率之间取得平衡
