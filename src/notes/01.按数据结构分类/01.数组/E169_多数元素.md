# E169. 多数元素

[LeetCode 题目链接](https://leetcode.cn/problems/majority-element/)

给定一个非空数组 `nums`，返回出现次数严格大于 `⌊n / 2⌋` 的多数元素。题目保证多数元素存在。

## 示例

```text
输入：nums = [3,2,3]
输出：3
```

```text
输入：nums = [2,2,1,1,1,2,2]
输出：2
```

## 提示

- `1 <= nums.length <= 5 * 10^4`
- `-10^9 <= nums[i] <= 10^9`
- 数组中一定存在多数元素

## 面试版思路

使用 Boyer–Moore 多数投票算法，模拟“两个不同元素相互抵消”。维护：

- `candidate`：当前未被抵消完的候选元素。
- `count`：候选元素在当前抵消结果中的剩余票数，不是它在整个数组中的真实频次。

遍历数组时：

1. 如果 `count == 0`，说明此前保留的候选票已经全部抵消，把当前元素设为新候选人。
2. 当前元素等于候选人时执行 `count++`。
3. 当前元素不等于候选人时执行 `count--`，表示二者抵消。

题目保证多数元素存在，所以最终可以直接返回 `candidate`。

## 为什么最终候选人一定是多数元素

设多数元素出现 `m` 次，其他所有元素合计出现 `n - m` 次。因为 `m > n / 2`，所以 `m > n - m`。

每次删除两个不同元素，最多消耗一个多数元素和一个其他元素。即使所有其他元素都与多数元素配对抵消，仍至少剩下：

```text
m - (n - m) = 2m - n > 0
```

因此，多数元素不可能被完全抵消，最后留下的候选人一定是它。中途候选人可以改变，这不影响最终结果。

## 示例推演

对 `[2,2,1,1,1,2,2]`：

| 当前数字 | candidate | count | 操作 |
|---:|---:|---:|---|
| 2 | 2 | 1 | 票数为零，选择 2，再加一票 |
| 2 | 2 | 2 | 相同，加一票 |
| 1 | 2 | 1 | 不同，抵消 |
| 1 | 2 | 0 | 不同，抵消 |
| 1 | 1 | 1 | 重新选择 1，再加一票 |
| 2 | 1 | 0 | 不同，抵消 |
| 2 | 2 | 1 | 重新选择 2，再加一票 |

最终返回 `2`。

## 代码要点

- `candidate` 在遍历过程中只是候选人，不能把它理解为已经确认的多数元素。
- `count` 表示抵消后的票数差，不是实际出现次数。
- 当 `count == 0` 时只更新候选人，当前元素随后会在统一的相等判断中贡献一票。
- 如果题目不保证多数元素存在，第一趟只能得到候选人，还需第二趟统计其真实频次并验证是否大于 `n / 2`。

## 本次自测发现的问题

### 新候选人被重复加票

最初在 `count == 0`、更新 `candidate` 后额外执行了一次 `count++`，而后续相等分支又会加一次，导致新候选人的第一票被错误计算两次。

正确做法是：更新候选人后继续进入统一判断，让下面的 `else` 只增加一次票数。

### 遗漏相同元素加票

最初只写了不同元素的 `count--`，遗漏相同元素的 `count++`。这样候选人无法积累优势，也就不能正确表达不同元素两两抵消后的票数差。

## 易错点

- 选出新候选人和给当前元素计票是两个概念，但当前写法会在后续统一判断中完成计票，不能重复增加。
- 相同元素必须加票，不同元素才减票。
- 不能把 `count` 当成候选人的真实频率。
- 没有“多数元素必定存在”的保证时，不能直接返回第一趟得到的候选人。
- 这不是寻找出现次数最多但可能不超过一半的元素；算法的直接结论依赖“严格超过一半”。

## 复杂度

- 时间复杂度：`O(n)`，只遍历数组一次。
- 空间复杂度：`O(1)`，只维护候选人和票数两个变量。

## 面试表达

我使用 Boyer–Moore 多数投票算法，把不同元素看作两两抵消。相同候选人加票，不同元素减票，票数归零时更换候选人。由于多数元素的数量大于其他所有元素数量之和，即使它们尽可能配对抵消，多数元素仍至少剩一个，所以最终候选人就是答案。题目保证答案存在，因此不需要第二次验证。
