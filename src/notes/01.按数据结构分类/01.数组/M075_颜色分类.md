# M075. 颜色分类

[LeetCode 题目](https://leetcode.cn/problems/sort-colors/)

给定只包含 `0、1、2` 的数组 `nums`，分别代表红、白、蓝。原地排序，使它们按 `0、1、2` 排列；不能使用库内置的 sort 函数。

```text
输入：[2,0,2,1,1,0]
输出：[0,0,1,1,2,2]

输入：[2,0,1]
输出：[0,1,2]
```

- `1 <= nums.length <= 300`
- `nums[i]` 为 `0、1、2`
- 进阶：常数额外空间、一趟扫描。

## 面试版思路

用左右边界和扫描指针维护四个区域，把遇到的 0 交换到左侧、2 交换到右侧，1 留在中间。这是荷兰国旗问题的三路划分解法，通常归入双指针类方法，本实现另有一个扫描指针。

## 区域不变量

| 范围 | 含义 |
|---|---|
| `[0, nextZero)` | 已归位的 0 |
| `[nextZero, i)` | 已检查的 1 |
| `[i, nextTwo]` | 未检查区域 |
| `(nextTwo, n - 1]` | 已归位的 2 |

初始化 `nextZero = 0`、`i = 0`、`nextTwo = n - 1`，整个数组都属于未检查区域。

## 三种操作

- 遇到 0：与 `nextZero` 交换，然后 `nextZero++`、`i++`。
- 遇到 1：只执行 `i++`。
- 遇到 2：与 `nextTwo` 交换，然后 `nextTwo--`，`i` 不动。

### 为什么交换 0 后可以前进

当 `nextZero < i` 时，`nextZero` 属于已经检查过的 1 区，换回来的必定是 1，可以直接纳入中间区域。当 `nextZero == i` 时只是自身交换，也不需要重新检查。

不能解释为“换回来无论是 1 还是 2，都应该在 0 后面”。如果真换回未知的 2，跳过它会漏掉将其送往右侧的处理；这里能够前进依赖的是已知区域不变量。

### 为什么交换 2 后不能前进

右边界属于未检查区域，换回来的可能是 0、1 或 2，必须留在原下标继续判断。例如 `[1,2,0]` 在处理下标 1 的 2 后变为 `[1,0,2]`，若直接前进，0 就不会被送到左侧。

## 正确性与复杂度

每个分支都保持上述四个区域的含义，并且让未检查区间长度 `nextTwo - i + 1` 减少一。当 `i > nextTwo` 时，未检查区间为空，只剩按顺序排列的 0、1、2 区。

- 时间复杂度：`O(n)`。虽然某个下标可能被重复检查，但每轮恰好排除一个未检查元素，总计 n 轮。
- 额外空间：`O(1)`，只使用三个下标和交换临时变量。
- 所有修改都发生在原数组中，无须返回新数组。

## 本次训练摘要

### 第一反应

能够判断 0 应送到左端、2 应送到右端，最初使用自动递增 i 的 for 循环，但不知道怎样表达“有时移动、有时不动”。

### 卡壳与修正

- 改用 while，由三个分支分别控制 i，而不是每轮统一递增。
- `nextTwo` 是下标，应为 `nums.length - 1`，不是数组长度。
- 循环检查 `[i, nextTwo]`，因此必须写成 `i <= nextTwo`；剩一个元素也要处理。
- i 要在 while 外声明。不能写成 `while (int i <= ...)`。
- 使用互斥的 `if / else if / else if`；若连续使用多个 if，前一个分支改变 i 后，后面的判断可能访问新下标，甚至越界。
- `swap(i, nextZero, nums)` 必须传入数组，和辅助方法签名对应。
- `void` 方法原地修改数组，不能 `return nums`。

### 关键突破

真正区分了“从左侧已知 1 区换回元素”和“从右侧未知区换回元素”，最终代码保留了区域不变量的解释。

## 面试表达

我维护左侧的 0 区、中间的 1 区、尚未检查区和右侧的 2 区。扫描到 0 就与左边界交换并移动两个指针，扫描到 1 就前进；扫描到 2 就与右边界交换并缩小右边界，但扫描指针不动，因为换回来的是未知元素。每轮未检查区域都减少一个元素，所以是 O(n) 时间、O(1) 空间。
