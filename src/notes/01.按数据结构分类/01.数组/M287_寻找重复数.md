# M287. 寻找重复数

[LeetCode 题目](https://leetcode.cn/problems/find-the-duplicate-number/)

数组长度为 n + 1，值域为 [1,n]，只有一个整数重复一次或多次。要求不修改数组、额外空间 O(1)，返回重复数字。

```text
[1,3,4,2,2] -> 2
[3,1,3,4,2] -> 3
[3,3,3,3,3] -> 3
```

<!-- codex-leetcode-start -->

## 为什么必有重复数字

n + 1 个元素只能取 [1,n] 中的 n 个值。根据抽屉原理，至少两个元素取值相同，因此一定存在重复数。

## 数组如何变成有环链表

把数组下标视为节点，把 `nums[i]` 视为从节点 i 指向节点 `nums[i]` 的边。因为每个值都在 [1,n]，从下标 0 出发始终不会越界，并最终进入环。

如果两个不同下标都存放重复值 d，它们都会指向节点 d；在从 0 可达的函数图中，节点 d 是环的入口。因此问题转换为寻找链表环入口。

```text
nums = [1,3,4,2,2]
0 -> 1 -> 3 -> 2 -> 4
               ^    |
               |____|
环入口为 2，也就是重复数字
```

## Floyd 两阶段

第一阶段让 slow 每次走一步、fast 每次走两步，直到在环内相遇：

```java
do {
    slow = nums[slow];
    fast = nums[nums[fast]];
} while (slow != fast);
```

第二阶段让一个指针回到起点 0，两个指针都每次走一步，再次相遇的位置就是环入口。

## 为什么第二次相遇是入口

设起点到入口距离为 a，入口到首次相遇点距离为 b，环剩余距离为 c。首次相遇时，快指针路程是慢指针的两倍，并比慢指针多走 k 圈：

```text
2(a + b) = a + b + k(b + c)
a = (k - 1)(b + c) + c
```

从起点走 a 步到入口；从相遇点走 a 步，则先走 c 到入口，再走若干整圈，仍停在入口。

## 本次训练摘要

- 用户记得快慢指针速度，但忘记相遇后的环入口查找，查阅后恢复了“两指针同步走”的步骤。
- 初稿正确完成两阶段 Floyd，但 `do...while` 末尾缺少分号。
- 初稿返回 `nums[slow]`；修正为 `slow`，因为第二次相遇的节点编号本身就是重复数字。
- 删除了多余的 `if (slow == fast)`：第一阶段退出时该条件必然成立。

## 易错点

- 第二阶段两个指针都走一步，不再使用一快一慢。
- 一个指针回到的是映射起点 0，不是 `nums[0]`。
- 返回 `slow`，不能返回 `nums[slow]`。例如 `[1,3,4,2,2]` 中入口为 2，而 `nums[2]` 是 4。
- 第一阶段若 slow、fast 都初始化为 0，应使用 `do...while`，否则未移动就会判定相遇。
- Java 的 `do...while` 结尾必须有分号。

## 复杂度

- 时间复杂度 O(n)：进入环和环内追赶、定位入口都是线性级。
- 额外空间 O(1)：只使用两个整数指针。
- 只读取 `nums`，不修改输入数组。

## 面试表达

我把下标视为节点，`nums[i]` 视为下一节点。由于值域合法，从 0 出发形成一条最终进入环的路径，而重复数字对应环入口。先用 Floyd 快慢指针在环内相遇，再让一个指针回到 0，两个指针同步前进，第二次相遇值就是重复数。算法 O(n) 时间、O(1) 空间且不修改数组。
