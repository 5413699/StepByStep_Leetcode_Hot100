131. 分割回文串

给你一个字符串 `s`，请你将 `s` 分割成一些子串，使每个子串都是回文串。

返回 `s` 所有可能的分割方案。

示例 1：

```text
输入：s = "aab"
输出：[["a","a","b"],["aa","b"]]
```

示例 2：

```text
输入：s = "a"
输出：[["a"]]
```

提示：

- `1 <= s.length <= 16`
- `s` 仅由小写英文字母组成

相关数据结构：字符串
方法：回溯、DFS、回文判断

## 面试版思路

这题可以用回溯枚举所有切割方案。递归参数 `start` 表示当前要从哪个位置开始切割，`cur` 记录当前已经选择的若干个回文子串。

在每一层递归中，固定切割起点 `start`，然后枚举终点 `end`，得到子串 `s[start..end]`。如果这个子串是回文串，就把它加入 `cur`，递归处理 `end + 1` 之后的剩余部分。递归返回后，再把刚才加入的子串移除，继续尝试下一个 `end`。

当 `start == s.length()` 时，说明整个字符串已经被切割完，并且 `cur` 中每一段都是回文串，所以把 `cur` 的快照加入 `ans`。

## 代码要点

- `start` 表示下一刀的起点，不是当前层的固定答案位置。
- 当前层 `for (int end = start; end < s.length(); end++)` 枚举所有可能的切割终点。
- `substring(start, end + 1)` 对应闭区间 `s[start..end]`，因为 Java 的 `substring` 是左闭右开。
- 选择一个回文子串后，下一层递归要从 `end + 1` 开始。
- 到达 `start == s.length()` 时，最后一段已经在上一层加入 `cur`，此时只负责把完整路径拷贝进答案。
- `new ArrayList<>(cur)` 是必要的快照；不能直接把可变的 `cur` 放入 `ans`。

## 易错点

- Java 方法名是 `substring`，不是 `subString`。
- `backtrack(s, ans, end, cur)` 没有真正推进状态；应该递归到 `end + 1`。
- 结束条件要放在递归函数开头。如果放进循环里，`start == s.length()` 时循环不会进入，反而加不到答案。
- 回溯时要移除刚才加入的最后一个子串，让当前层继续尝试下一个更长的切割终点。

## 复杂度

设字符串长度为 `n`：

- 时间复杂度：最坏可以理解为 `O(2^n * n^2)`。切割方案数量是指数级，每次尝试子串时还会判断回文并创建子串。
- 空间复杂度：不算答案为 `O(n)`，主要是递归深度和当前路径；如果计算答案存储，最坏也是指数级。
- 优化方向：可以预处理 `dp[i][j]` 表示 `s[i..j]` 是否回文，把回文判断降到 `O(1)`。

## 掌握状态

- 状态：提示后完成，需要二刷。
- 当前主要突破：理解最后一个元素不是在结束条件里加入的，而是在上一层递归选择时已经进入 `cur`；结束条件只负责验收完整路径。
- 当前主要卡点：`substring` 方法名和右开边界、递归推进到 `end + 1`、结束条件应该放在递归函数开头。
- 面试表达：基本可用，已经能说清楚固定起点、枚举终点、选择回文前缀、递归剩余部分、回溯撤销。
