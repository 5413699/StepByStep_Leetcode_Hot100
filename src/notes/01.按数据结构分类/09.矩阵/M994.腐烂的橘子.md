994. 腐烂的橘子

在给定的 `m x n` 网格 `grid` 中，每个单元格可以有以下三个值之一：

- 值 `0` 代表空单元格；
- 值 `1` 代表新鲜橘子；
- 值 `2` 代表腐烂的橘子。

每分钟，腐烂的橘子周围 4 个方向上相邻的新鲜橘子都会腐烂。

返回直到单元格中没有新鲜橘子为止所必须经过的最小分钟数。如果不可能，返回 `-1`。

示例 1：

输入：`grid = [[2,1,1],[1,1,0],[0,1,1]]`

输出：`4`

示例 2：

输入：`grid = [[2,1,1],[0,1,1],[1,0,1]]`

输出：`-1`

解释：左下角的橘子永远不会腐烂，因为腐烂只会发生在 4 个方向上。

示例 3：

输入：`grid = [[0,2]]`

输出：`0`

解释：因为 `0` 分钟时已经没有新鲜橘子了，所以答案就是 `0`。

提示：

- `m == grid.length`
- `n == grid[i].length`
- `1 <= m, n <= 10`
- `grid[i][j]` 仅为 `0`、`1` 或 `2`

## 题干

给定一个只包含 `0`、`1`、`2` 的二维网格，其中 `0` 表示空格，`1` 表示新鲜橘子，`2` 表示腐烂橘子。每分钟所有腐烂橘子都会让上下左右相邻的新鲜橘子腐烂。返回让所有新鲜橘子腐烂所需的最少分钟数；如果存在永远无法腐烂的新鲜橘子，返回 `-1`。

## 思路

先遍历整个网格，把所有初始腐烂橘子加入队列，作为多源 BFS 的起点，同时统计新鲜橘子的数量。

然后按层进行 BFS，每一层表示一分钟。每次取出当前这一分钟会向外扩散的腐烂橘子，检查它上下左右四个方向。如果新坐标越界或不是新鲜橘子，就跳过；如果是新鲜橘子，就将它变成腐烂橘子，新鲜橘子数量减一，并加入队列，作为下一分钟继续扩散的起点。

每处理完一层，时间加一。最后如果新鲜橘子数量为 `0`，返回时间；否则说明存在无法腐烂的新鲜橘子，返回 `-1`。

## 思考过程

一开始的直觉是：先遍历网格，找到腐烂橘子和新鲜橘子的位置，然后每一轮让所有腐烂橘子向四周扩散。这个方向是对的，本质就是 BFS。

卡壳点主要在实现结构上：

- 坐标不能写成 `List<Integer, Integer>`，更适合用 `Queue<int[]>` 存储坐标。
- 遍历网格时应该访问 `grid[i][j]`，不能写成 `grid[m][n]`。
- 不需要保存所有新鲜橘子的位置，只需要用 `freshCount` 记录剩余新鲜橘子数量。
- 每轮 BFS 必须先固定 `int size = queue.size()`，否则循环中加入的新腐烂橘子会被当成同一分钟继续扩散，导致分钟数错误。
- 上下左右四个方向适合用方向数组统一处理，避免手写四组坐标时把方向写错。

关键突破是把“每轮遍历所有腐烂橘子”转成“队列按层扩散”：初始所有腐烂橘子同时入队，作为多源 BFS 的第 `0` 分钟起点；每处理完当前队列的一层，才说明过了一分钟。

## 题解

```java
class Solution {
    public int orangesRotting(int[][] grid) {
        int m = grid.length;
        int n = grid[0].length;
        int minTime = 0;
        Queue<int[]> rot = new LinkedList<>();
        int freshCount = 0;
        int[][] dirs = {{1,0},{-1,0},{0,1},{0,-1}};

        for(int i = 0; i < m; i++){
            for(int j = 0; j < n; j++){
                if(grid[i][j] == 2){
                    rot.offer(new int[]{i,j});
                }
                if(grid[i][j] == 1){
                    freshCount++;
                }
            }
        }

        while(!rot.isEmpty() && freshCount > 0){
            int size = rot.size();
            for(int i = 0; i < size; i++){
                int[] cur = rot.poll();
                int x = cur[0];
                int y = cur[1];

                for(int[] dir : dirs){
                    int rotx = x + dir[0];
                    int roty = y + dir[1];
                    if(rotx < 0 || rotx >= m || roty < 0 || roty >= n){
                        continue;
                    }
                    if(grid[rotx][roty] != 1){
                        continue;
                    }

                    grid[rotx][roty] = 2;
                    freshCount--;
                    rot.offer(new int[]{rotx,roty});
                }
            }
            minTime++;
        }

        if(freshCount == 0){
            return minTime;
        }
        return -1;
    }
}
```

## 复杂度

时间复杂度：`O(mn)`，每个格子最多入队一次。

空间复杂度：`O(mn)`，队列最坏可能保存整个网格中的橘子。

## 易错点

- 这是多源 BFS，初始所有腐烂橘子都要加入队列，而不是只从某一个腐烂橘子开始。
- BFS 按层计时，必须先记录当前层 `size`，不能在 `for` 条件里动态使用 `queue.size()`。
- 每腐烂一个新鲜橘子，需要立刻标记为 `2`，避免它被其他腐烂橘子重复加入队列。
- 如果一开始没有新鲜橘子，`freshCount == 0`，循环不会进入，最终返回 `0`。
- 如果队列耗尽后仍有新鲜橘子，说明这些橘子无法被腐烂，返回 `-1`。
