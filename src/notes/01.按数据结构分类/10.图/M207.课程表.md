207. 课程表

你这个学期必须选修 `numCourses` 门课程，记为 `0` 到 `numCourses - 1`。

在选修某些课程之前需要一些先修课程。先修课程按数组 `prerequisites` 给出，其中 `prerequisites[i] = [ai, bi]`，表示如果要学习课程 `ai` 则必须先学习课程 `bi`。

例如，先修课程对 `[0, 1]` 表示：想要学习课程 `0`，你需要先完成课程 `1`。

请你判断是否可能完成所有课程的学习？如果可以，返回 `true`；否则，返回 `false`。

示例 1：

输入：`numCourses = 2, prerequisites = [[1,0]]`

输出：`true`

解释：总共有 2 门课程。学习课程 1 之前，你需要完成课程 0。这是可能的。

示例 2：

输入：`numCourses = 2, prerequisites = [[1,0],[0,1]]`

输出：`false`

解释：总共有 2 门课程。学习课程 1 之前，你需要先完成课程 0；并且学习课程 0 之前，你还应先完成课程 1。这是不可能的。

提示：

- `1 <= numCourses <= 2000`
- `0 <= prerequisites.length <= 5000`
- `prerequisites[i].length == 2`
- `0 <= ai, bi < numCourses`
- `prerequisites[i]` 中的所有课程对互不相同

## 题干抽象

每门课程可以看成图中的一个节点，`prerequisites[i] = [ai, bi]` 表示学习 `ai` 之前必须先学习 `bi`，所以边的方向是：

```text
bi -> ai
```

也就是：学完 `bi` 之后，才可能解锁 `ai`。

题目问“能否完成所有课程”，本质是在问这个有向图中是否存在环。如果存在环，说明有一组课程互相等待，永远无法全部学完；如果不存在环，就可以找到一种合法的学习顺序。

## 思路

使用入度数组和队列做拓扑排序。

- `graph`：记录每门课可以解锁哪些后续课程。
- `indegree`：记录每门课当前还剩多少门前置课程没有完成。
- `queue`：保存当前入度为 `0`、可以直接学习的课程。

先根据 `prerequisites` 建图。对于 `[course, pre]`，边是 `pre -> course`，因此：

```java
graph.get(pre).add(course);
indegree[course]++;
```

然后把所有入度为 `0` 的课程加入队列。每次从队列中取出一门课，表示这门课已经学完，`learned++`。接着遍历它能解锁的后续课程，把这些课程的入度减 `1`。如果某门后续课程的入度变成 `0`，说明它的所有前置课程都已经学完，可以加入队列。

最后判断 `learned == numCourses`。如果相等，说明所有课程都能学完，返回 `true`；否则说明剩下的课程被环卡住，返回 `false`。

## 思考过程

一开始没有做过这个类型，先把题目从“课程学习”翻译成“有向图依赖”。关键是理解 `[ai, bi]` 的方向：不是 `ai -> bi`，而是 `bi -> ai`。

用例 `numCourses = 4, prerequisites = [[1,0],[2,0],[3,1],[3,2]]` 可以画成：

```text
0 -> 1
0 -> 2
1 -> 3
2 -> 3
```

初始入度是：

```text
0: 0
1: 1
2: 1
3: 2
```

所以课程 `0` 可以先入队。学完 `0` 后，课程 `1` 和 `2` 的入度都从 `1` 变成 `0`，可以入队。学完 `1` 和 `2` 后，课程 `3` 的入度从 `2` 逐步减到 `0`，最后也可以学习。最终学完 `4` 门课，说明无环。

本题的关键突破是：入队只表示“当前可以学”，出队才表示“真的学完了”。只有学完一门课之后，才可以让它指向的后续课程入度减 `1`。

## 题解

```java
class Solution {
    public boolean canFinish(int numCourses, int[][] prerequisites) {
        List<List<Integer>> graph = new ArrayList<>();
        int[] indegree = new int[numCourses];
        Queue<Integer> queue = new LinkedList<>();

        for (int i = 0; i < numCourses; i++) {
            graph.add(new ArrayList<>());
        }

        for (int[] prerequisite : prerequisites) {
            int course = prerequisite[0];
            int pre = prerequisite[1];

            graph.get(pre).add(course);
            indegree[course]++;
        }

        for (int i = 0; i < numCourses; i++) {
            if (indegree[i] == 0) {
                queue.offer(i);
            }
        }

        int learned = 0;
        while (!queue.isEmpty()) {
            int cur = queue.poll();
            learned++;

            for (int nextCourse : graph.get(cur)) {
                indegree[nextCourse]--;
                if (indegree[nextCourse] == 0) {
                    queue.offer(nextCourse);
                }
            }
        }

        return learned == numCourses;
    }
}
```

## 复杂度

时间复杂度：`O(numCourses + prerequisites.length)`。每门课最多入队、出队一次，每条依赖边最多被遍历一次。

空间复杂度：`O(numCourses + prerequisites.length)`。邻接表保存所有课程和依赖边，入度数组和队列最多保存 `numCourses` 个元素。

## 易错点

- `[course, pre]` 的方向是 `pre -> course`，不要写反。
- `indegree[course]++`，不是 `indegree[pre]++`。
- `graph` 初始化时要先放入 `numCourses` 个空 `List`，否则无法通过课程编号直接 `graph.get(i)`。
- `learned++` 应该放在出队时，因为出队才表示真正学完这门课。
- 队列为空不一定代表失败；队列为空只是拓扑排序结束，只有 `learned < numCourses` 时才说明存在环。
- 图本身不需要真的删边，只需要把后续课程的入度减 `1`。

## 面试表达

这道题可以抽象成有向图判环。每门课程是一个节点，先修关系 `[ai, bi]` 表示边 `bi -> ai`。如果图中存在环，就会出现课程之间互相依赖，无法完成所有课程；如果没有环，就可以按拓扑序学习。

我使用入度数组和队列做拓扑排序。先建邻接表并统计每门课的入度，把所有入度为 `0` 的课程加入队列。每次取出一门课表示学完它，然后把它指向的后续课程入度减 `1`，如果后续课程入度变成 `0`，就加入队列。最后如果学完的课程数等于 `numCourses`，返回 `true`，否则说明有环，返回 `false`。
