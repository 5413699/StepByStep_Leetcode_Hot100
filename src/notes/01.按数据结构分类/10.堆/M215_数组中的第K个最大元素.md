215. 数组中的第 K 个最大元素

给定整数数组 `nums` 和整数 `k`，请返回数组中第 `k` 个最大的元素。

请注意，需要找的是数组排序后的第 `k` 个最大的元素，而不是第 `k` 个不同的元素。

你必须设计并实现时间复杂度为 `O(n)` 的算法解决此问题。

示例 1：

```text
输入：nums = [3,2,1,5,6,4], k = 2
输出：5
```

示例 2：

```text
输入：nums = [3,2,3,1,2,4,5,5,6], k = 4
输出：4
```

提示：

- `1 <= k <= nums.length <= 10^5`
- `-10^4 <= nums[i] <= 10^4`

## 面试版思路

这题可以先想到大小为 `k` 的最小堆：遍历数组时把元素加入堆，元素数量超过 `k` 就弹出堆顶。最终堆中保存最大的 `k` 个元素，堆顶是其中最小的，也就是第 `k` 大元素。该方案时间复杂度是 `O(n log k)`，不满足题面要求的线性时间，但它帮助建立了堆顶和淘汰对象之间的关系。

为了达到期望 `O(n)`，最终使用随机化快速选择。第 `k` 大元素在升序数组中的目标下标是 `nums.length - k`。每次在当前闭区间 `[left, right]` 随机选择 `pivot`，通过三路分区把区间划分为小于、等于、大于 `pivot` 的三个区域。若目标下标位于等于区域，直接返回；否则只继续处理目标所在的一侧，不需要完整排序。

三路分区维护四个区域：

```text
[left, leftIndex - 1]       < pivot
[leftIndex, cur - 1]        == pivot
[cur, rightIndex]           尚未判断
[rightIndex + 1, right]     > pivot
```

`cur` 表示当前正在判断的位置，`leftIndex` 表示下一个小元素应放置的位置，`rightIndex` 表示尚未判断区域的右边界。遇到大元素时，将它交换到 `rightIndex` 并缩小右边界，但 `cur` 不能增加，因为从右边交换回来的元素还没有判断。循环结束后 `[leftIndex, rightIndex]` 就是所有等于 `pivot` 的元素所在范围。

## 代码要点

- `target = nums.length - k`，把“第 `k` 大”转换成升序目标下标。
- `random.nextInt(right - left + 1)` 生成从 `0` 到区间长度减一的随机偏移，再加 `left` 得到闭区间内的随机下标。
- 主循环只根据目标和等于区域的位置关系更新 `left` 或 `right`。
- 分区循环必须使用 `cur <= rightIndex`，当两者相等时仍有一个元素尚未判断。
- 小元素交换到 `leftIndex` 后，交换回 `cur` 的元素来自已经确认的等于区域，因此 `leftIndex` 和 `cur` 可以同时增加。
- 大元素交换到 `rightIndex` 后，交换回 `cur` 的元素来源于尚未判断区域，因此只能执行 `rightIndex--`，不能执行 `cur++`。

## 易错点

- 这是快速选择，不是快速排序；快速选择每轮只继续处理目标所在的一侧。
- 固定选择最右侧元素作为基准，在有序数组上可能退化为 `O(n^2)`，所以使用随机基准。
- 普通二路分区会在大量重复元素时反复只缩小一个位置，因此最终采用三路分区并返回等于区域。
- `Random.nextInt(bound)` 的上界 `bound` 不包含在结果中，所以闭区间长度必须写成 `right - left + 1`。
- `leftIndex` 始终小于等于 `cur`；等于区域是 `[leftIndex, cur - 1]`，不包含当前尚未判断的 `cur`。
- 返回的是等于 `pivot` 的下标范围 `{leftIndex, rightIndex}`，主循环需要和范围两端比较。

## 复杂度

- 最小堆方案：时间复杂度 `O(n log k)`，空间复杂度 `O(k)`。
- 随机化快速选择：期望时间复杂度 `O(n)`，最坏时间复杂度 `O(n^2)`；迭代实现的额外空间复杂度为 `O(1)`。
